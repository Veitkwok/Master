# X 检索策略（操作符与手艺）

> 供 `GUIDE.md` 使用。Bot 的 X 读取器支持这些操作符；不支持时退回"账号时间线 + 关键词"两招。

## 1. 常用操作符

| 操作符 | 用法 | 例子 |
|--------|------|------|
| `from:` | 指定账号 | `from:BabybusFL` |
| `since:` / `until:` | 时间窗（UTC 日期） | `since:2026-10-08` |
| `-filter:replies` | 去掉回复 | `$NVDA -filter:replies` |
| `min_faves:` | 互动下限（发现/降噪） | `$NVDA min_faves:100` |
| `$TICKER` | 精确代码 | `$PLTR` |
| 引号短语 | 精确短语 | `"data center" $MRVL` |
| `lang:` | 语言过滤（可选） | `lang:en` |

组合优先级：`from:` 或 `$TICKER` + 时间窗 + 去回复；先用最窄的查询，不够再放宽。

## 2. 三种读取模式

| 模式 | 步骤 | 预算 |
|------|------|------|
| 账号扫描（routine 默认） | 读时间线 → 截断才补主帖 | 1–2 次/账号 |
| 关键词发现 | `$TICKER` / 公司名 + 时间窗 + 去回复 → 需要时 `min_faves` | 2–4 次 |
| 主题研究（ad-hoc） | 语义/关键词 x2 → 打开 1–2 条高价值线程 | 8–15 次 |

## 3. 降噪

- 丢弃：纯 emoji/口号、纯转发无评论、推广/付费群链接、明显 bot 复读。
- 同一句模板在多个号重复出现：标 `risk_flags: coordinated_hype`，只当线索。
- 争议账号/黑历史号：保留原句但标 `reliability: low`。
- 时间窗外的旧帖：不当作本轮证据。

## 4. 引用纪律

- 每条引用必须能给出 `url`（或 post id）+ `posted_at` + 作者 handle。
- 引用帖内数字时保留原句；不要"翻译成结论"。
- 打不开原帖就不引用；不要用搜索结果摘要冒充原文。

## 5. 失败处理

- 读取器报错/限流：记录 `source_error`，该账号本轮跳过；不要重试轰炸。
- 账号改名/找不到：记录一次，继续其他账号；不要在 routine 里追查。
